# Normalisation / standardisation / preprocessing inventory (YCT, end to end)

Status: inventory for the agent-council recheck of normalisations. It is label-free. It was built only from
ROADMAP.md, DECISIONS.md, config.yaml, docs/prompts/v2.md, docs/tribe_requirements.md, src/yct/**, scripts/**
and reviews/**, plus `git diff` of config/code against the P2/P3 run commit b24fc1c. Nothing was read from
data/sealed/, labels or outcomes, transcript text, pred_clampv1/ arrays or analysis-set outputs/ statistics
(firewall D-063 B2).

Columns:
- **Where** = file:line, then the config key and its config.yaml line, then the decision id.
- **Frozen**:
  - Y = a `frozen:` row in config.yaml (check_frozen_config.py enforces it);
  - code = a hard-coded constant (protected only by review or a manifest blob sha);
  - N = editable;
  - spec = text only, with no code.
- **Consumers**: H1–H4 and H4b = v2.md §1. T3 = the photometric sensitivity track. P4b(a–d) = the controls. LOC = the P9 localisation outputs. S-* = sensitivities.

Counts: **33 stimulus-side, 23 model-side (M-01–M-22 plus M-12b) and 25 analysis-side items, 81 in total.** Of these, 10 are spec-only or partly unimplemented: S-24, S-31, M-20, A-10, A-11, A-15, A-18, A-20, A-21, and the hdr_source arm of A-05. The rest are implemented.

## Notes for the council (preliminary; inventory facts, not verdicts)

**N1. Freeze coverage.** P2/P3 has already consumed these keys:
- `normalize.*`;
- `stimulus.{fps, min_short_side_px, center_crop_px, t1_trim_s, t1_max_probe_s}`;
- `vad.*`, `confounds.*`, `features.*`, `atlases.*`, `localize.*`, `m0.*`.

The run was D-060, git b24fc1c. None of these keys is in `frozen:`. I checked: they are byte-identical between b24fc1c and HEAD (yaml compare). The only P2/P3 code change since then is the equivalent `word_rate_per_tr` refactor in 4db5895. They are therefore protected only by convention.

D-071 also names `controls.kernel.window_tr` and `controls.readout_lag_tr` as the single sources of the lags and the (d) readout. Neither key is frozen. Also unfrozen:
- `controls.kernel.type` and `controls.kernel.shift_by_L`;
- `controls.partial_out`;
- `controls.regressors.{face, luminance_change, speech_envelope}`;
- the FFC/PH/AUD/V1_V3 area lists. Only their vertex counts are frozen, through `rois_per_hemi`.

**N2. Specified but not yet implemented** (these need code + tests before P5/P6):
- P4b (a)–(d) (A-18, A-20) and the speech envelope (A-21);
- the H2 composite (M-20; no config key either);
- M0b (A-11);
- CV-fold scaling (A-10);
- the Freedman–Lane PCs (A-15);
- `hdr_source` in M0 (A-05/S-10);
- the espeak SpeechProvider, including resampling and span trim (S-24).

**N3. Recorded but never consumed.** These are produced but no analysis reads them. v2.md calls crop coverage "a confound" and 9:16 "its own stratum", so each needs an explicit decision: consume it, or demote it to QC-only.
- crop coverage (S-07);
- `stratum_9x16` (S-08);
- the `upscaled` flag;
- source bitrate/codec/resolution, which v2.md P2 says are "logged per video as confounds";
- mono-phase and A/V-sync flags (S-15, S-17);
- the q480 copy (S-18).

**N4. Redundant with respect to TRIBE's own transforms** (they may still be justified for other consumers):
- **Upscaling to a 292 short side (S-06).** V-JEPA2 resizes to 292 anyway. S-06 mainly fixes the geometry for the confounds and T3 statistics.
- **Loudness normalisation (S-14).** For TRIBE it is a no-op up to the per-chunk z-score (M-01). The exception is any video where loudnorm fell back to dynamic mode: that changes within-chunk dynamics. The per-video count of `loudnorm_mode` was not read here (P2 records are analysis-set outputs).
- **CFR 30 (S-05).** TRIBE does not need it, because sampling is time-based; it serves determinism.
- **`rms_db` in M0.** It is largely equalised by S-14, as the `m0.merge_list` rationale itself says.

**N5. Possible correctness issues to verify:**
- **Speech duration check (S-23/S-24).** `clip_audio` checks the full synthesised length (refclips58.py:328-331), while corpus selection uses the −40 dBFS span. RMS matching and the uniform word timings also use the full length. The provider must trim to the span before placement, or espeak's leading and trailing silence shifts word onsets and inflates speech gain.
- **Reference-clip colour tags (S-22).** Reference clips carry no colour tags. This is harmless for greyscale content (Cb = Cr = 128, and range defaults to tv), but it is not "the P2 T1 output spec".
- **Duplicate standardisation (M-12b).** The P4b kernels must use the M-12 function for d_std, not the `enh002.standardise` duplicate.
- **Scene cuts (A-01).** `scene_cuts` is computed on the full frame, while every other visual M0 feature is computed in the crop.
- **No drift term in P4b(a) (A-18).** The within-video partial r has an intercept only, no drift or onset-transient term.
- **Re-estimation scope (A-17).** It is not stated whether subset sensitivities and wave 2 re-estimate the z-scores, imputation medians and Q, or reuse wave 1's.
- **TRIBE's decoder matrix (M-02).** It is unverified, but S-09 makes inputs consistent either way.

**N6. Choices to disclose rather than fix:**
- T3 gray-world and gain are computed on gamma-encoded values, not linear light (S-19).
- SHINE runs on the hard-edged square patch with no aperture (S-27).
- Localiser images get no ICC handling (S-26).
- Map colour scales are per map (A-22).

Out of scope: curation hashing (company_key, the one-per-company pick) and determinism guards beyond M-09, because neither transforms stimuli or responses.
