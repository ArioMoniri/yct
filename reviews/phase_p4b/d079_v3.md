# D-079 v3: addendum to d079_v2.md after the council re-check (wf_4ef7126f-cea)

Status: draft for the second re-check. Nothing is frozen and DECISIONS D-079 is not written. No v2 filter call
has been made, so no rule below was chosen with a v2 outcome in view.

The re-check verdicts were APPROVE from Watchdog, Referee and Neuroscientist, and REVISE from the
Biostatistician (B1, B2) and QA (B1). This addendum leaves `d079_v2.md` unchanged and amends only the
sections named below. Every other part of v2 stands.

## A. §2.7 file identity (amended): a pre-stated reject, not a STOP (Biostat B1)

- **Rule** (`identity_rule: reject_identity_changed`). Before any other rule, the snapshot `sha1` must equal
  the current Commons imageinfo `sha1`. After download, it must also equal the sha1 of the downloaded bytes.
  - On a mismatch, the row is logged as a reject with rule `D1` and reason `identity_changed` (no
    detector values), and the run continues at the next rank.
  - Every such row is disclosed in the v1 report, with its title, both sha1s and the stage at which the
    mismatch was found (metadata or bytes).
- **Missing data is still a STOP.** A missing snapshot or Commons sha1 is a STOP naming the title
  (`ra.identity_ok`).
- **The reason list is amended, not edited.** The new reason `identity_changed` sits in
  `controls.refclips_d079.extra_reject_reasons`. The frozen D-071 `refclips.reject_reasons` list is not
  edited; the schema refuses an extra reason that repeats a frozen one, and `finalise` passes the extra
  reasons to `rs.check_log`.
- **QA's objection,** that a reject adds a reason outside the frozen list, is answered by stating the rule
  now, before any v2 call. It cannot depend on which file it removes. Watchdog, Referee and Neuroscientist
  accepted STOP, and Biostat accepted either rule if it is pre-stated. The council chose the pre-stated
  reject because a STOP would leave the next step to be decided after a result is seen. This choice is
  recorded here for the second re-check.
- **Audit.** A v2 `identity_changed` row is a different file from the one v1 judged, so the audit exempts
  it, whatever the v1 row says.

## B. §2.11 (new): how each STOP is resolved, stated before the v2 run (Biostat B1)

The config key is `controls.refclips_d079.stop_resolution`. Each rule has a test.

| STOP | Resolution |
|---|---|
| Identity mismatch (`identity_mismatch`) | `reject_identity_changed_resume_next_rank` (§A). Not a STOP. |
| Revision moving within a batch (`lastrevid_moved`): a lastrevid change between template-paging responses, or a C4 extmetadata revision different from the read revid (§D) | `retry_batch_once_then_stop_to_council`. The whole 50-title batch holding the title is queried once more. A second move is a STOP to the council naming the title (`rs.page_meta_c4`). |
| Any other determinism-audit STOP (`other_audit_stop`) | `code_defect_bug_entry_v3_from_rank_1`. The STOP is treated as a code defect: a BUG entry is filed, and a v3 run starts from rank 1 for every category under §2.8 (finality) and is disclosed. The STOP message says so. It is never resolved for one title at a time. |

All other STOPs are unchanged and stay fail-closed: missing data, a truncated response, a decode or
download failure, an environment or artifact mismatch, and fewer than 20 passes. Each goes to the owner,
and a v3 is allowed only under §2.8.

A single retry of a revision read is not a selection. It runs before the title is evaluated and does not
depend on any filter outcome.

## C. §3 audit (amended): duplicate exempt only when the other side is not a C1 reason (Biostat B2)

C1 runs before C3, so a `duplicate` reason implies C1 was passed. A `duplicate` on one side and a C1
reason on the other is therefore an admissibility change, not an ordering effect. The exemption now needs
both of these:

- one side's reason is `duplicate`;
- the other side's reason is not in `c1_reasons`.

This ends two silent allowances:

| v1 | v2 | Before | Now |
|---|---|---|---|
| `duplicate` | `licence` / `personality_rights` | exempt | STOP (admissible to inadmissible) |
| `licence` / `personality_rights`, not listed | `duplicate` | exempt | STOP (unlisted flip) |
| `licence`, in the flip list | `duplicate` | allowed (listed flip) | allowed, unchanged |

## D. Revision of the C4 metadata (Watchdog N3)

The C4 extmetadata query now also requests `prop=info`. Its lastrevid must equal the `read_revid` of
the templates request. A mismatch is a revision move and is handled by §B (one batch retry, then a STOP to
the council). This puts the C4 text and the licence on the same revision. The code is
`rs.page_meta_c4`, which the runner now calls.

## E. Strict `log_version` in preload (QA B1, Watchdog N2)

`ra.preload_v2` accepts a row only if `r.get("log_version") == "v2"`, with no default. Real v1 rows carry
no `log_version` key, which a test confirms on the three committed v1 logs. A v1-shaped row in a v2 log is
now a STOP at preload, before any evaluation.

## F. Titles in STOP messages (QA, non-blocking)

The STOP messages for identity, read revid, revision move, missing download URL and decode failure now
name the file title. A truncated or unterminated batch names its first and last title.

## H. Addendum after the final sign-off (wf_7797c743-b64; append-only; referee B1/B2, QA B1)

- **§A is narrowed to the metadata stage.** `identity_changed` (rule D1) applies only when the snapshot
  sha1 differs from the current Commons imageinfo sha1, i.e. the file was re-uploaded since the snapshot.
  Such a row is decided before any download: `identity_stage: "metadata"`, `data_sha1: null`.
- **Byte stage = download defect, never a reject.** Once the snapshot and Commons sha1s agree, downloaded
  bytes with a different sha1 (or a stale cached file) are deleted and downloaded once more
  (`ra.fetch_verified`). If they still differ, the run STOPs, naming the title. This matches every other
  download failure, which is a STOP. §B's `identity_mismatch` row now covers the metadata stage only; the
  byte stage falls under "any other STOP = defect" (BUG entry, v3 from rank 1).
- **Disclosure implemented.** `finalise` writes `data/refstim/image_identity_changed_v2.json`: for each
  category, the list of identity_changed rows (title, snapshot sha1, Commons sha1, stage, data sha1) or
  `"none"`. A row without `identity_stage`/`data_sha1` STOPs finalise. The v1 report quotes this file.
- **Tests:** `tests/test_refstim_d079_signoff.py` holds 9 new tests, written first and failing first.
  `test_identity_reject_row` in `tests/test_refstim_d079_recheck.py` now also asserts the two new keys (a
  stricter assertion; nothing was removed).
