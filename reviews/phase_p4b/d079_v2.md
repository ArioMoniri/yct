## 3. Determinism audit v2 vs v1 (Watchdog 4, Referee 1, Biostat R1, QA 1)

The audit is kept, not retired. It is fail-closed and non-selecting: it can only STOP, never change a
decision. It is implemented in `ra.audit_v2` and called on every v2 row before the row is appended.

- **Baseline:** for each v2 row, the row for the same title in every superseded log of its category:
  - face: the face log;
  - body: both body logs;
  - place: none, because no v1 place log exists.
- **Exempt flip list:** `data/refstim/bug036_c1_flips.json`, the committed BUG-036 re-check output.
  - For each v1 log it lists, by sha256(title), the titles whose C1 reading went inadmissible →
    admissible (`inadm_to_adm`), plus `adm_to_inadm` and `revid_changed`.
  - Its sha is frozen before the run (`flip_sha256`). It is never inferred at run time.
  - `rs.load_flips` refuses a sha mismatch, a missing or extra log, or a non-empty `adm_to_inadm`, which
    would mean v1 over-admitted. That case is a STOP to the owner.
- **Rules** (per v1 log containing the title):

| Case | Result |
|---|---|
| Title in that log's `inadm_to_adm` list, v1 reason in C1 (licence / personality_rights) and v2 reason not C1 | allowed: the later rules are new evaluations |
| Title in the list but v1 reason not C1, or v2 still C1 | STOP (contradicts the committed re-check) |
| (decision, reason) equal | allowed |
| Either reason `duplicate` | allowed (C3 depends on the passes before it) |
| Anything else: admissible in v1 but C1 in v2; a C1 reason change; any non-C1 change; pass ↔ reject | STOP to the owner |

- **Revid drift is not an exemption.** A title whose page was edited since the snapshot (2 face rows in the
  re-check) must still reproduce its v1 non-C1 decision, or the run STOPs. This may stop the run. It is
  accepted, because it is the conservative reading.
- **This amends D-078 §3 and §5:** D-078's audit compared only against the D-074 body log, exempting only
  `duplicate`. Under the fixed client it would STOP by construction on the 108 body flips.

These counts come from the read-only re-check at e768363. The flip file
`data/refstim/bug036_c1_flips.json` (sha256 e7ce5c2a…2067, set in `refclips_d079_artifacts.flip_sha256`, not yet

Tests check the sha, the sizes, and that every listed title is a v1 C1 reject in its log.

**What was compared each time:**

- **BUG-036 diagnosis (BUGS.md):** 32 face rows changed admissibility, 18 inadmissible → admissible and 14
  admissible → inadmissible.
  - This compared two truncated readings with different batch boundaries against each other. Run 2 resumed
    after row 8, which shifted every batch.
  - Truncation removes templates from whichever titles fall late in a batch. Moving the boundaries moves the
    damage, so both directions appear.
- **Re-check (this table):** compares the reading stored in each v1 row with the complete reading from the
  fixed client.
  - A complete reading can only add templates that a truncated reading lost. So it can turn inadmissible
    into admissible.
  - It could turn admissible into inadmissible only if truncation had hidden a Personality rights template.
    That happened 0 times.
- **So "v1 only under-admitted" holds against the complete reading.** The 14 were titles that one truncated
  reading admitted and the other did not; the complete reading admits them.
